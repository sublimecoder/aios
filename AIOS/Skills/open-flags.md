# open-flags

**Purpose:** ⚠️/OPEN markers in project notes are commitments, not decorations. Each one names a fact that must be confirmed, reconciled, or acted on ("confirm with the owner", "parity gap", "reconcile before trusting this bullet") — left unswept, they rot into permanent hedges nobody re-checks.

**Two modes, and they are deliberately separate.** *Disposition* runs inside every ingest and is bounded by the project being ingested. *Escalation* is a standalone pass over the whole corpus, and it does **not** run inside an ingest. Same split as [[km-rotate]] and [[log-rollup]]: `aios-check.sh` detects, a standalone run acts.

**A marker inside a provenance/Source section is NOT a flag — exclude those sections from the grep in both modes.** `source-history.md`, its monthly archives (`source-history-YYYY-MM.md`, rotated out by [[provenance-rollup]] and carrying exactly the same kind of lines), **sections relocated whole into a `_history/` directory beside the shard** (`provenance-rollup`'s `--extract` mode — e.g. `<scope>/projects/<project>/_history/km-activity-trail.md`; `_history` must be the file's IMMEDIATE parent, so `incident_history/` is not exempt), and any `## Source` section record what an ingest *did to* flags ("✅ resolved 1 — the ACME-1508 marker", "All other ⚠️ markers pre-existing"), so a reference to a flag gets counted as one. That file alone carried 88 such lines, roughly a third of the project's apparent flag load, all false positives. This supersedes nothing about blame validity — an appended provenance entry does keep valid blame dates (see Mode B) — it simply means those lines were never in the flag population to begin with.

## Mode A — disposition (inside [[aios-ingest]], step 1e)

1. Grep the ingested project's note(s) for the flag markers: `⚠️`, `OPEN —`, `OPEN:`, `parity gap` — **skipping provenance/Source sections** per the rule above.
2. **Disposition the flags whose TOPIC the ingested queue touches**, individually: either *confirmed still open* (the digest doesn't resolve it; leave it) or *resolved in the note* (the digest settles it; rewrite the flagged bullet to the settled fact and record the resolution in the Source section). **Record the remainder as confirmed-still-open in ONE line**, not one line per flag.
   - **Why this is the contract and not a shortcut.** The old wording — *no flag on a touched project passes an ingest unsighted* — is unachievable at real scale: the largest project carries 257 flag lines across 19 shards, and no unattended run inspects them one by one. Every run has therefore improvised exactly the method above and none of them wrote it down, so it was re-invented per run and the honest version never reached the skill. A contract a run cannot meet is not a stricter contract; it is one that gets quietly replaced by an undocumented one.
   - A flag's topic is touched when the queue's commits, mirror files, or synthesis bear on the same subsystem, ticket, or decision the flag names. When in doubt it is touched — the cost of one extra disposition is a paragraph, the cost of a missed one is a stale hedge nobody re-checks.
3. Report the per-project tally in the ingest report: dispositioned individually / carried en bloc. **Do not escalate here** — see below for why.
   - **A sweep RECORD goes in the note's `## Source` section, never in its body.** A record *of* a flag ("✅ resolved 1 — the ⚠️ marker from the 08-02 run", "all other ⚠️ markers pre-existing") carries the same markers as a live flag, so written into the body it greps as one forever, and no amount of reading tells the two apart. Placement is the whole fix: the exclusion at the top of this skill already exempts a provenance/`## Source` section, and since 2026-08-16 `aios-check.sh` implements that same section rule — so a record written there is silent in **both** consumers by construction, with no new marker to invent and no existing marker to migrate. A **sharded** project has no `## Source` section in its shards; its records belong in `source-history.md`, which both consumers already exclude by path. **Never invent a second marker for this** — the flag vocabulary has nine consumers and ~300 existing lines, and a convention only half-adopted under-reports the register, which is the worse failure direction.

## Mode B — escalation (standalone; trigger "sweep the flags")

1. Grep `*/projects/**/*.md` for the markers, **excluding provenance/Source sections** (see the rule above the modes — a reference to a flag is not a flag). One layer at a time.
2. Age each flag. `git blame` on the flag's own line is the anchor, but **it is a LOWER BOUND, not the age**: **a shard an ingest rewrites IN PLACE resets those lines' blame; an APPENDED entry does not.** (That corrected an earlier claim here that step 1g's appends made `source-history.md`'s dates worthless — appends keep valid blame. It is now moot for that file anyway: its markers are provenance, excluded from the population at step 1. Both facts stand; only one is load-bearing.) Derive first-seen from [[Log]] or the note's Source section for lines a rewrite actually touched, and mark "unknown" when neither settles it.
3. Flags past 30 days: append one row per flag to **`AIOS/History/audits/flag-register.md`**, proposing close-or-act. Set the row's `Date source` column to `stamp` when the flag's age came from its inline `⚠️ (YYYY-MM-DD)` birth date, or `blame` when it came from `git blame` author-time (step 2). Update an existing row's age rather than adding a second.
   - **Age the "fix exists only as uncommitted scratch" class too — it is the one that hides.** A flag whose remedy sits in a working tree (uncommitted on a branch with no commits, or re-typed by hand across several sessions) reads as active work every time it is seen, so it never looks stale — while the actual artifact is one `git checkout` from gone. Third recurrence of that signature by 2026-08-05. Treat "the fix is uncommitted N days" as its own escalation reason independent of the flag's own age: an abandoned working tree should age **visibly** rather than be silently re-typed.
4. Report the register (open / resolved-since-last-sweep / newly escalated).

**Why escalation is NOT an ingest step (settled 2026-08-07).** Step 4 used to append one dated line to [[Log]] per aged flag, per run, and **had never once fired** — read as agent laziness for weeks; it was arithmetic. The corpus is younger than the threshold: on 2026-08-07 the oldest flag anywhere blamed to 07-15, 23 days. Nothing had aged out yet. But **275 flags exist and 32 cross 30 days within a fortnight**, so the first firing would have dumped ~32 lines into `Log.md` inside an unattended run — the file the SessionStart hook reads on every session, and the one [[log-rollup]] exists to keep lean. A nag channel and a decision record cannot be the same file. The register absorbs the volume; [[Log]] gets one line per sweep.

**Constraints:** read-only over the notes, with two exceptions — an ingest-driven resolution (Mode A step 2, only when the digest genuinely settles it) and rows written to the flag register (Mode B step 3). Never silently delete a flag: a flag leaves a note only by being resolved into a settled fact, and the resolution is recorded. One layer at a time when run standalone.

**Dependencies:** the layers' `projects/` dirs, [[aios-ingest]] (calls Mode A per touched project), `AIOS/Systems/aios-check.sh` (reports the aging count that triggers Mode B), [[Log]] (first-seen dates; one summary line per sweep). **Output:** dispositioned flags in the notes; rows in `AIOS/History/audits/flag-register.md`.
