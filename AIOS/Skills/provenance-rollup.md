# provenance-rollup

**Purpose:** keep a project's provenance shard lean. [[aios-ingest]] reads the whole shard every run to dedupe, so the cheapest question in the pipeline gets more expensive with every run — one project's shard reached 264,162 bytes across 86 entries before this skill existed. [[km-rotate]] and [[log-rollup]] both drain *into* this shard; this is the drain it lacked. Entries are the audit trail and are never lost, only rotated into monthly archives.

**Entry anchors — the one definition, used by every step below:**

```
^(## |From the |Also from the |Synthesized from the |\*\*⚠️ OUT-OF-BAND)
```

An entry is one anchor line plus everything up to the next anchor (or EOF). The bytes before the first anchor are the *preamble* and never move.

**Run it with the tool, not by hand:**

```
python3 AIOS/Systems/provenance-rotate.py work/projects/<Proj>/source-history.md            # dry run
python3 AIOS/Systems/provenance-rotate.py work/projects/<Proj>/source-history.md --apply
python3 AIOS/Systems/provenance-rotate.py <shard> --extract '## <heading>' <shard-dir>/_history/<slug>.md          # dry run
python3 AIOS/Systems/provenance-rotate.py <shard> --extract '## <heading>' <shard-dir>/_history/<slug>.md --apply
python3 AIOS/Systems/provenance-rotate.py --selftest
```

It implements every step below, prints the three-part proof, and refuses to write if any assertion fails. **Hand-editing is not a fallback:** the live shard holds a single 45,364-character line and 213 unicode-bearing lines, so byte-exact reproduction through a Write call is not a real operation, and one wrong character silently corrupts the audit trail. The steps below are the contract the tool implements — read them to review it, not to replace it.

**Steps:**
1. Count anchors in the shard — the before-count. Record the preamble length and the entry-body total (file bytes − preamble). Conservation is checked against both, so both are captured *before* anything moves.
2. Move every entry whose **content date** is older than the current month into `source-history-YYYY-MM.md` beside its parent. The content date is the `ingested YYYY-MM-DD` clause **if it occurs on the anchor line**, else the first `YYYY-MM-DD` on the anchor line. **Scope the extractor to the anchor line, never the entry body** — two entries in one observed shard carried their only `ingested` match inside the body as a cross-reference to an earlier ingest, so a first-match-in-entry regex reads the wrong date. Slice to the first newline so a body match is unreachable *by construction* rather than filtered out afterwards. **A body-scoped bug here lies dormant:** both cross-references happen to name an in-month date, so the split is correct today and the bug would first misfile an entry at a month boundary — long after the run that introduced it. Where an anchor carries both a UTC stamp and a local window date, use the local one. **Entries are not in date order** — rotate and stay runs interleave (one observed shard flips class five times), so select by date, never by position, and keep each set in its original relative order.
3. Never alter entry text — not a character. Entries are the audit trail; rotation moves them, it does not edit them. The archive carries the parent's frontmatter fields verbatim (`tags`, `type`, `layer`, `project`, `parent`, `updated`) plus a rotation-date line. No archive preamble line may itself match the anchor regex, or it inflates the archive's anchor count.
4. Leave the live shard with: frontmatter + `# Source` preamble, the current month's entries in their original order, and a pointer line at the bottom listing the archives newest-first — `Older: [[source-history-2026-07]] · …` — updated to include every archive that exists. Leave `updated:` alone unless the newest entry actually moved; a frontmatter edit is a **declared byte delta**, never incidental.
5. **Verify — three parts, all required.** (a) *Count*: anchors across the live shard + every archive equals the before-count. (b) *Bytes*: entry-body bytes across those files equals the before-total, delta exactly 0 — a non-zero delta is byte loss or preamble contamination, never rounding. (c) *Content*: `sha256` of the archive with its preamble stripped equals `sha256` of the rotated spans concatenated from the pre-move file. **Equal byte totals do not prove equal bytes** — (a) and (b) both pass on a rotation that silently altered content, which is the whole reason (c) exists. Write the archive and verify it **before** truncating the live shard, on a clean tree, so a partial write never finds the live file already gone.
6. Commit as its own commit (Co-Authored-By trailer) and log a dated line in [[Log]]: `- **YYYY-MM-DD** — **aios/provenance-rollup** — rotated N entries into source-history-YYYY-MM.md.`

**Constraints:** the current month never rotates — [[aios-ingest]] dedupes against the live shard, so the newest entries must always be there. Entry text is immutable. Never delete an archive. `source-history-YYYY-MM.md`, beside its parent, is the only new-file destination. If any conservation assertion fails, `git checkout` and stop — report the failure rather than reconstruct, because a reported failed rotation is recoverable and a silently wrong one is not.

**The write path — and what actually guards it.** Both files sit under a layer dir. `vault-write-guard.sh` Rule F refuses any Bash *write shape* naming them, and Rule D once refused the archive too (it rejects work-note content carrying a bare `#NNNN` or `PR #NNNN`, and the pre-2026-08 entries carry 21 of the former and 3 of the latter in already-committed text) — between them the rotation had no legal path at all. Rule D gained a narrow carve-out on 2026-08-09: it skips a target whose **basename** matches `source-history-YYYY-MM.md` exactly, or whose **immediate parent directory** is exactly `_history`. Rule D governs notes people write, not archives the OS moves.

**Do not read that carve-out as the thing protecting the live shard, because it is not.** `provenance-rotate.py` writes both files with Python `open(...,'wb')`, and Rule F permits the *invocation* (the shard path is a plain argument, not a write shape), so **Rule D never sees either file's bytes on this path** — not the archive's, and not the live shard's. The carve-out matters only for a hand-written `Write` call to an archive; it is not a runtime check on the rotation. Concretely: if a future month's staying set ever carries a `#NNNN`, **nothing will block the truncation** — the tool will write it and Rule D will stay silent. The real protection is the conservation proof (entry text is never edited, and assertion (c) fails if a byte changes), not the guard. If you want Rule D enforced on that content, check it in the tool; do not expect the hook to do it.

**When to run it — the trigger is now mechanical.** `aios-check.sh --verbose` lists every project shard over **100KB** (archives exempt by name: `-YYYY-MM.md` and anything under `_history/`). Until 2026-08-11 nothing said a shard had grown too big, so nothing ever did: the Knowledge Map has [[km-rotate]] and a byte gate, the Log has [[log-rollup]] and a month boundary, but the shards an ingest reads and rewrites *every run* had neither, and they only ever grow — `domain-tenancy.md` went 145KB → 193KB in six days, monotonically, and holds a single 8371-byte line. The check is verbose-only and never fails a session: the shards already over it are a standing backlog rather than drift, and **which sections are settled history versus live standing state is a judgment call this skill exists to make.** The number points; you decide. Past 256KB a shard can no longer be opened whole by an agent's Read tool, so the backlog is not only a token cost.

**CONTENT-shard mode — `--extract`, and its scope is narrower than the check's.** A topical shard (`domain-tenancy.md`, `frontend-conventions.md`, `ci-quality-gates.md`) carries no dated entries, so the monthly rotation above can never reach it. The second mode moves **one settled `## <heading>` section out whole**, and four of its rules are enforced by the tool rather than by convention. **The destination must sit in `_history/` beside the shard, and must not already exist** — `<shard>-<period>.md` next to the parent is refused outright, so do not propose that shape. **The shard must be under a scope's `projects/` or `notes/`**: a shard outside those two dirs that the check names has **no sanctioned writer**, and widening that is a guard change, not a flag — say so rather than hand-rotating it. The heading prefix must match **exactly one** section (two matches or none both exit). And the shard must be **clean against `git HEAD`**, because the pre-move fingerprint comes from `git show`, not from the file being rewritten. One section per run; re-run for the next. What lands: the section byte-identical under the shard's own frontmatter, a non-anchor `Moved: … now lives in [[…]]` pointer where it was, and a printed proof of span, `sha256`-vs-`HEAD` and longest-line equality before anything is written.

**Dependencies:** the project shard (`source-history.md` for the monthly rotation; any `work/projects/` content shard the size check names for `--extract`), [[aios-ingest]] (the wire that appends to it), [[open-flags]] + `AIOS/Systems/aios-check.sh` (whose flag-population exclusion the archive inherits — the glob there matches the shard with or without a `-YYYY-MM` suffix, so a new archive does not re-enter the flag count; and whose shard-size line is the trigger above). **Output:** a leaner live shard + monthly archives, anchor count and entry bytes preserved exactly, content proved identical by hash.
